# Gongfu Cha Lab — Предметная модель (Domain Model)

**Версия:** 0.1.1-audit  
**Статус:** Аудит предметной модели и достоверности данных (Этап 1.1)  

---

## 1. Фундаментальные принципы достоверности данных

### 1.1. Градация происхождения данных (Data Origin Hierarchy)
Любая физическая или химическая величина в системе сопровождается строгим метаданным о происхождении:

1. **`MEASURED` (Лабораторное измерение)**:
   Применяется **только** при наличии проверяемого первичного источника: протокола испытаний конкретной партии, лабораторного отчёта, идентифицируемого набора данных с указанием методики (ВЭЖХ, рефрактометрия, титрование) и сведений об исследованном образце. Названия аналитических методов без привязки к протоколу не дают права называть значение измеренным.
2. **`LITERATURE` (Литературный справочный источник)**:
   Данные из рецензируемых публикаций, монографий и академических баз по биохимии чая (например, обобщённые диапазоны культиваров Camellia sinensis). Обязательно сопровождаются библиографической ссылкой или указанием академического источника.
3. **`MODEL_PROFILE` (Типовой профиль / Допущение модели)**:
   Ориентировочные величины, используемые для демонстрационных сценариев и предварительных расчетов до проведения физической калибровки. В интерфейсе явно маркируются как допущение модели и не выдаются за подтверждённые факты.
4. **`USER_DEFINED` (Пользовательский ввод)**:
   Значения, явно введённые пользователем вручную. Статус `user_defined` **не присваивается** значениям, подставленным системой по умолчанию.
5. **`UNKNOWN` (Неизвестное значение)**:
   Значение отсутствует. Численное поле `value` строго равно `null`.

### 1.2. Принцип «Неизвестное не равно нулю» (`Unknown ≠ 0`)
В физико-химических расчетах отсутствие замера параметра (например, содержания теанина или жесткости воды) не означает нулевое значение. Модель запрещает подставлять $0$ вместо неизвестных данных.

### 1.3. Отказ от фиктивных оценок уверенности и доверительных интервалов
- Запрещено автоматически присваивать значениям показатель `confidence = 1.0`.
- Одиночный показатель уверенности нельзя называть доверительным интервалом.
- Оценка неопределенности (`uncertainty`) указывается только при наличии реального протокола измерений (погрешность прибора, стандартное отклонение выборки $\pm \sigma$).

## 2. Предметная модель чайного образца (`TeaSample`)

### 2.1. Разделение физических и химических понятий
1. **Общий потенциально экстрагируемый сухой остаток (`totalExtractableFraction`)**:
   Предельная доля водорастворимых сухих веществ в % от массы сухого листа (типично 30–45% для Camellia sinensis).
2. **Отдельные химические компоненты (`caffeineFraction`, `totalPolyphenolsFraction`, `theanineFraction`)**:
   Выражаются строго в **% от массы сухого листа**. Они являются частью растительной ткани и входят в состав общего экстракта. **Запрещён двойной подсчёт:** сумма отдельных компонентов не может складываться сверх общего сухого остатка.
3. **Физическое водопоглощение матрицы (`waterAbsorptionRatio`)**:
   Масса воды, физически связываемая 1 г сухого листа при гидратации и набухании матрицы (г/г).
4. **Удержание жидкости после слива (`liquorHoldUpAfterDrain`)**:
   Объём раствора, капиллярно удерживаемый в зазорах между листьями после полного слива настоя.
5. **Насыпная плотность (`leafBulkDensityGPerCm3`)**:
   Плотность сухого листа в незатрамбованном насыпном объёме навески (г/см³), отличающаяся от истинной плотности растительной ткани.
6. **Скорость смачивания (`uncalibratedHydrationSpeed`)**:
   Внутренний некалиброванный безразмерный параметр модели. Не является обязательным свойством чая и не навязывается пользователю при создании образца.

### 2.2. Упрощённая модель пользовательского чая
Для обычного пользователя создание чая не требует знания химии и кинетики. Доступные поля:
- Название чая (обязательно);
- Категория (если известна, с возможностью «Не указано / Не знаю»);
- Форма листа (если известна, с возможностью «Не указано / Не знаю»);
- Регион, культивар, производитель (если известны);
- Год сбора и год производства (если известны; **запрещено** автоматически подставлять текущий год);
- Степень обжарки и технологические особенности обработки.
- **Исключены субъективные дегустационные заметки:** личные вкусовые впечатления удалены из формы и доменной модели, так как они не являются физическими параметрами.

## 3. Раздельные модели методов заваривания

Каждый метод моделируется собственной событийной или пошаговой структурой:

### 3.1. Метод Гунфу Ча (`GongfuSessionConfig`)
- Последовательность импульсных проливов:
  `GongfuStepConfig { stepNumber, infusionTimeSeconds, pourWaterVolumeMl, waterTemperatureC }`.
- После каждого пролива настой полностью сливается.
- Соотношение листа к воде рассчитывается строго по **фактическому объёму заливки**, а не по паспортной вместимости чайника или гайвани.

### 3.2. Метод Лю Гэнь Пао (`LiuGenPaoSessionConfig`)
- Пошаговое сохранение «корней настоя»:
  `LiuGenPaoStepConfig { stepNumber, infusionTimeSeconds, addedWaterVolumeMl, addedWaterTemperatureC, retainedLiquorFractionOfTotal }`.
- **Однозначное определение удержания:** процент удержания $r$ рассчитывается строго относительно **ПОЛНОГО объёма жидкости в сосуде перед сливом**:
  $$V_{\text{total}, k} = V_{\text{retained}, k-1} + V_{\text{added}, k}$$
  $$V_{\text{retained}, k} = V_{\text{total}, k} \cdot r_k$$
  $$V_{\text{drained}, k} = V_{\text{total}, k} \cdot (1 - r_k)$$
  Остаток настоя не является долей свежедолитой порции воды.

### 3.3. Метод открытого заваривания в кружке (`LazyMugSessionConfig`)
- Не является серией независимых проливов. Листья непрерывно находятся в кружке.
- Моделируется непрерывной временной шкалой с дискретными событиями:
  - `initial_pour` — первоначальное заливание листьев водой;
  - `sip_consumption` — отпивание части напитка (уменьшение объема);
  - `water_refill` — долив свежей горячей воды указанного объёма и температуры;
  - `session_end` — завершение сессии.
- Между событиями экстракция непрерывно продолжается, а температура падает.
- Демонстрационный график глотков явно обозначается как **модельное допущение**, а не запись реальных действий пользователя.

## 4. Профиль химического состава воды (`WaterProfile`)

- Параметры воды являются независимыми: TDS (мг/л), общая жесткость dGH, карбонатная жесткость dKH, pH, концентрации ионов $Ca^{2+}$, $Mg^{2+}$, $HCO_3^-$. Запрещено выводить химический состав только из TDS.
- Предусмотрены явно обозначенные типовые профили с флагом `isModelPreset: true`, сообщающим, что это оценочный сценарий.
- Предусмотрен нейтральный профиль `water-user-custom`, где не указанные пользователем величины остаются строго `unknown` (`value: null`).
